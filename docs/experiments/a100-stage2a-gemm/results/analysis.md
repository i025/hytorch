## 源码观察（不是性能测量）

`gemm_basic` 每个线程计算一个输出，沿 K 串行累加，直接读 global memory。没有线程块级显式 shared-memory 复用。重复读取输入以及串行累加依赖可能限制性能，但缓存、编译器和硬件调度的实际作用尚未测量。

`gemm_blocked` 将输出组织为二维 tile，并分块遍历 K，但仍从 global memory 读输入，没有显式将块存入 shared memory。分块本身不保证减少实际 DRAM 流量或提高吞吐。

`gemm_shared` 协作装载 A/B tile 到 shared memory，重复使用 tile 数据；每个 K 块有两次同步。Tile 16 为每块 256 线程，Tile 32 为每块 1024 线程。复用收益、同步开销、寄存器需求和驻留块数可能共同影响结果；没有 profiler 数据时不声称其中某项就是瓶颈。

本轮未修改或优化任何 GEMM kernel。下一步先在空闲单卡上得到完整数据，再区分观察事实、源码解释和待验证假设。
