# 预先固定的实验协议

基线 d26667f160bf3af772ad24685f73049f6267a11a。保留原 Gather，不增加或修改 CUDA Kernel。

`scripts/cases.py` 定义32个校准、20个独立验证形状。初版16个验证形状保留在 predeclared-shapes.json；在任何验证计算及规则冻结之前，第二版另增4个包含未见 Batch2/8、通道8/24/48的插值验证形状，保存为 predeclared-shapes-02.json。校准首批已执行，但扩展时未读取任何验证延迟。先只执行校准；冻结规则 JSON 后才执行独立验证，不用验证延迟调整规则。所有形状只使用算子参数标识，执行路径不接收模型名或层号。

候选规则先限定为单一工作量阈值：`N*Cin*H*W*Cout*Kh*Kw/(Sh*Sw)`。它是含边界浪费的工作量代理，不是精确 FLOPs。按该特征排序，仅将从最小工作量开始、校准证据一致支持 Gather 的连续区间纳入规则。原/Gather 完整同步墙钟均取3个独立进程的均值；每进程5次预热、30次测量。需要至少10%平均优势，且三个 Gather 进程均值均低于三个 original 的均值，作为超出观测波动的保守筛选，不称为统计置信区间。

若单阈值没有可靠区间，或者独立验证出现明确退化，则只交付分析，不强行集成 auto。独立验证必须同时包含被选择的 Gather 与保留 original 的形状；对选中 Gather 的形状，平均完整墙钟应改善至少5%，不可出现超过5%的明确回退。接近波动的校准形状保留 original。

规则仅在校准支持的连续 FP32 NCHW/OIHW、groups=1、dilation=1、stride1/2、padding0/1和明确形状边界内生效；未覆盖输入明确走 original 并记录选择原因。默认 original 不变，显式 fused 保留原检查，高阶图保留可微路径，输入剪枝先于调度。

CUDA Event 跨度包括主机提交间隙，不冒充纯 Kernel 核时。普通计时、Nsight 设备事件、内存 hook 独立测量。PyTorch/cuDNN只作对照和算法选择设计参考，不承担 HyTorch 的计算，也不启用逐调用在线调优。

架构参考：[PyTorch benchmark 选择](https://docs.pytorch.org/docs/main/backends.html)、[NVIDIA cuDNN execution plan heuristics](https://docs.nvidia.com/cudnn/latest/developer/overview/)。本轮借鉴算法与选择器分离、依据算子属性选算法；不用其在线搜索或执行引擎。

## 第二候选与全新验证集

单阈值在独立 h10 上只有3.47%墙钟优势，未达预先5%门槛；该失败记录保留，不放宽阈值。此后已观测的32+20个形状统一作为第二候选训练数据，旧20个不再称作第二候选的独立验证集。

源码中每线程沿 Cout 串行 FMA 的事实，以及校准 c26 与 c03 工作量相近但性能差异显著的观察，支持增加 `Cout*Kh*Kw` 串行工作代理。只拟合两个单调条件 `work<=T && serial<=S`：枚举训练集观测到的 S，对每个 S 仍取全满足原10%/重复分离门槛的工作量前缀，选择覆盖最多训练形状者（同数时选择累计节省更大者）。不读取新验证数据。

`predeclared-shapes-03.json` 另固定24个从未计时的新形状 validation-2，其中3个超出校准包络，用于验证明确保留 original。第二候选在2026-10-29 18:41:05 UTC冻结：T=10,321,920、S=576、训练选中33/52。新验证的5%余量规则保持不变。只有这组全新验证及实际运行回归均通过，才允许接入默认关闭的实验 auto；否则保留分析。

## 最终受限候选与停止规则

第二候选的全新验证也未通过：v10 的完整墙钟143.555→154.985 μs，v13优势未到5%门槛。该较宽规则没有接入后端。

最终候选不再拟合阈值，沿用首轮 T=1,161,216，仅在1×1、stride1、padding0和原校准包络内选择 Gather，其他全部 original。其依据是已测 pointwise 家族的结果一致，且源码中不存在空间归约循环；不把这一证据外推到3×3/5×5。`predeclared-shapes-04.json` 固定最后24个全新验证形状；旧76个都不是它的独立验证证据。最终候选18:48:08 UTC冻结，24形状独立测试选中14个，全部满足不变的5%门槛。只在这一步完成后增加 auto 接口。

不再增加其他候选。实际 auto 的每调用元数据开销纳入新的四方法、三重复点算子测量，再执行五方法跨模型训练和 GPU 回归。默认 original 保持不变；若实际 auto 回归失败，不以换容差或再改独立验证门槛解决。

上述百分比门槛具体定义为 `original_wall / fused_wall - 1`，即耗时比所对应的吞吐余量，不与墙钟下降百分比混用。
