# CPU 调度原型的拓扑适用范围

这是已有 heap 原型的补充验证，没有新增第二个优化。全部在 CPU 上运行，GPU NOT_RUN。
测试使用独立的链式、残差、平衡树及扇出结构，每节点分别为 128 或 8192 个 FP32 元素。
五次独立重复，交替 list/heap 顺序；每次三轮预热、三十轮完整 Forward+Backward。
不含 SGD、数据 I/O 或 GPU 提交，不能称为 CNN 训练加速。

## 数值与计时

12 组配置的 Loss 和输入梯度共 24 项逐元素一致。完整数值数组留服务器。
所有原始计时均保留，没有选择性丢弃慢次，也没有按结果调整调度规则。

## 解释与保留决策

原 list 路径每加入 Function 都按 generation 排序，队列宽时会反复遍历现有元素。
heap 保持相同 generation 优先级与 LIFO 平局顺序，减少宽队列的排序工作。
相同数量级的 Function、不同 ready 队列宽度表现明显不同；单凭图节点数预测收益并不可靠。
节点数组增大时实际数值计算占比增加，宽图的相对吞吐收益也随之降低。

保留显式 `using_config('backward_schedule', 'heap')` 实验选项，默认仍为 list。
不加入基于模型名称、图宽度的自动切换，不把这项 CPU 原型自动加入 J 的 GPU 组合。

## CPU 分配代价

单独使用 tracemalloc 测量 Backward 期间创建的跟踪分配，构图在跟踪前完成。
每个模式先两次预热，三次交替独立重复，不将带内存插桩的耗时计入性能结果。
这不是进程 RSS、总历史分配量或 GPU 显存。

|---|---|---|---|
| chain256 / 128 | 146640、146472、146472 | 146500、146500、146500 | 极小；不称内存收益 |
| tree256 / 128 | 248812、248812、248812 | 271640、271640、271640 | +22828 bytes |
| fanout256 / 128 | 248812、248812、248812 | 271640、271640、271640 | +22828 bytes |
| chain256 / 8192 | 275552、275552、275552 | 275580、275580、275580 | +28 bytes |

| fanout256 / 8192 | 8538128、8538128、8538128 | 8561488、8561488、8561488 | +23360 bytes |
