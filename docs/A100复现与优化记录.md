## GEMM 优化与配对测量

修改 `hytorch/backends/cuda/kernels.cu`：M/N/K 均至少为 64 时，shared 路径使用
64×64 输出块、16×16 线程块，每线程累加 4×4 输出；K 分块仍为 16 或 32。
寄存器复用减少共享内存读取。小矩阵保留原内核，basic/blocked 消融实现保持原样。
保留 FP32、累加顺序、当前 stream 和 ABI，没有启用 TF32 或 fast-math。

固定 seed=42+size，预分配输出，每个库预热 3 次，10 次正式重复交替执行两个版本。
CUDA event 中位数不包含 H2D/D2H。这是原生 shared 实现的版本间对比，不是相对 cuBLAS 的加速结论。

| 方阵边长 | K tile | 原版 ms | 优化版 ms | 加速比 |
|---|---:|---:|---:|---:|
| 1024 | 16 | 0.759 | 0.424 | 1.79× |
| 1024 | 32 | 0.698 | 0.407 | 1.72× |
| 2048 | 16 | 5.808 | 2.541 | 2.29× |
| 2048 | 32 | 3.979 | 1.881 | 2.12× |
| 4096 | 16 | 32.801 | 13.290 | 2.47× |
| 4096 | 32 | 29.300 | 12.040 | 2.43× |

六组输出与原版逐位一致。新增测试覆盖 64 边界、M/N/K 尾块、预分配输出及非默认 stream。
完整重复耗时见 `gemm_paired/comparison.csv`。

### 保留的大矩阵数值门限问题

原始 `bench_cuda_gemm.py` 使用 NumPy FP32 参考与逐元素 `atol=rtol=1e-4`。
1024 通过；2048/4096 时，原版 CuPy 和各 native 实现均有失败。
4096 原版相对 NumPy 最大绝对差约 0.00116，相对 L2 误差约 1.19e-6。
本轮没有修改这个门限，也没有把失败输出标为通过。

补充的 `bench_cuda_revisions.py` 单独报告原门限，并以完整 FP64 矩阵乘法为参考：
2048/4096 相对 L2 误差约 8.10e-7 / 1.15e-6，优化前后逐位一致。
版本回归检查要求逐位一致且 FP64 相对 L2 <= 1e-5；**它不代替原始严格门限验收**。
失败不是本次优化引入的数值回归；后续应单独明确长 FP32 点积的误差验收标准。

## 合成训练

同一 256 个合成样本、固定初始化和顺序、FP32、batch=4、SGD lr=0.001、dropout=0。
每次 3 epochs（768 样本处理），预热 10 steps 后恢复初始权重。
每组 3 次，第二轮反向排列组顺序；throughput 模式，硬件采样间隔 0.2 秒。
PyTorch 禁用 TF32，cuDNN 使用确定性设置。下表为训练 epoch wall time，包含每步日志及 loss 读取开销。

| 实现 | 平均 wall 秒 ± 样本标准差 | samples/s | 对原 native 比 |
|---|---:|---:|---:|
| HyTorch 原 native | 0.97689 ± 0.00496 | 786.2 | 1.000× |
| HyTorch 优化 native | 0.98227 ± 0.00257 | 781.9 | 0.995× |
| HyTorch CuPy | 0.98196 ± 0.00306 | 782.1 | 0.995× |
| PyTorch | 0.55470 ± 0.00754 | 1384.5 | 1.761× |

优化前后最终权重逐位一致，最终 epoch loss 均为 0.000381266。
CuPy/PyTorch 相对原 native 最大权重绝对差分别为 4.19e-8 / 2.98e-8。
所有组通过相同配置核对与 `atol=1e-4, rtol=1e-3` 最终权重对齐。

**没有测得端到端训练加速。** 单独 64 样本 phases 诊断中，反向占 56.5%，前向约 26.0%。
当前优化只影响满足尺寸条件的前向 GEMM，不能将大方阵收益外推到训练。
后续优先用时间线分析反向卷积的 im2col/tensordot、Python 调度及小 kernel 启动开销，
再设计独立的反向算子优化。短 phases 诊断只有 1 个硬件采样点，不据此推断 GPU 利用率。

## 复现命令

从仓库根目录执行，输出目录必须不存在。先在原始提交构建并保存 baseline 库，再切回优化源码构建。
本轮已保存 `runs/a100_20261106/libhytorch_cuda_baseline.so`。

```bash
source /home/xieminhui_pubuse/hytorch-env/bin/activate
export CUDA_VISIBLE_DEVICES=1 CUDA_PATH=/usr/local/cuda
export PATH=/usr/local/cuda/bin:$PATH
export LD_LIBRARY_PATH=/usr/local/cuda/lib64
export OPENBLAS_NUM_THREADS=4 OMP_NUM_THREADS=4
python scripts/build_cuda.py --arch 80
python scripts/validate_cuda.py --output runs/recheck_01
python benchmarks/bench_cuda_revisions.py \
  --baseline runs/a100_20261106/libhytorch_cuda_baseline.so \
  --candidate hytorch/backends/cuda/build/libhytorch_cuda.so \
  --output runs/paired_02
python benchmarks/bench_cuda_ops.py --batches 1 4 16 --repeats 10 --output runs/ops_02
python benchmarks/bench_cuda_training.py --model donkey --samples 256 --epochs 3 \
  --batch 4 --warmup 10 --mode throughput --interval 0.2 \
  --matmul shared --conv im2col --pool native --output runs/donkey_synthetic_02
```

原版训练对照设置 `HYTORCH_CUDA_LIBRARY` 指向 baseline 库。
CuPy 对照省略三项 native 参数；PyTorch 省略三项 native 参数并加 `--framework torch`。
实际命令存于 `baseline_commands.json` 和 `remaining_commands.json`，本地汇总脚本为 `summarize.py`。
真实数据任务精度、ImageNet 权重转换和迁移训练、其他 GPU 架构不在本轮结论范围内。
